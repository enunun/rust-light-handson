# Iteration 0：内容アドレスとblob

Iteration 0では，ファイルの内容からGitのオブジェクトIDを計算する．
このノートでは，Gitがファイルの内容をどう識別するかを，本物の`git`で確かめながら説明する．

## 内容アドレス

Gitは，ファイルの内容をオブジェクトとしてデータベースに格納する．
オブジェクトには，内容から計算したハッシュを名前(ID)として付ける．
内容が同じなら名前も同じになり，内容が1バイトでも違えば名前も変わる．
このように，中身から決まる名前で中身を探す仕組みを内容アドレス(content-addressable)と呼ぶ．

`git hash-object`は，ファイルをオブジェクトにしたときのIDを表示する．
同じ内容の2つのファイルは同じIDになり，末尾の改行がないだけのファイルは別のIDになる．

```console
$ printf 'hello\n' > hello.txt
$ cp hello.txt copy.txt
$ printf 'hello' > nonl.txt
$ git hash-object hello.txt
ce013625030ba8dba906f756967f9e9ca394464a
$ git hash-object copy.txt
ce013625030ba8dba906f756967f9e9ca394464a
$ git hash-object nonl.txt
b6fc4c620b67d95f953a5c1c1230aaab5db5a1b0
```

`git hash-object`はリポジトリの外でも動く．`--stdin`を付けると，ファイルの代わりに標準入力を読む．

```console
$ printf 'hello\n' | git hash-object --stdin
ce013625030ba8dba906f756967f9e9ca394464a
```

内容アドレスには次の性質がある．

- 同じ内容は1回だけ格納すればよい．100個のコミットに同じファイルがあっても，オブジェクトは1つである．
- 名前を見れば中身が壊れていないかを確かめられる．中身からハッシュを計算し直して，名前と比べればよい．
- 名前は中身を変えない限り変わらない．Gitの履歴が書き換えにくいのは，このためである．

## blobオブジェクト

ファイルの内容を表すオブジェクトをblobと呼ぶ．
blobはファイルの中身だけを持ち，ファイルの名前やモードは持たない．名前はIteration 4で扱うtreeオブジェクトが持つ．

Gitは，オブジェクトの中身の前に次のヘッダーを付けたバイト列のハッシュを，オブジェクトIDにする．

```text
blob <中身のバイト数>\0<中身>
```

`<中身のバイト数>`は10進数の文字列で，`\0`はバイト値0(NUL)である．
`hello\n`は6バイトなので，ハッシュを計算するバイト列は次のようになる．`xxd`は，バイト列を16進数と文字で表示する．

```console
$ printf 'blob 6\0hello\n' | xxd
00000000: 626c 6f62 2036 0068 656c 6c6f 0a         blob 6.hello.
```

このバイト列のSHA-1を`sha1sum`で計算すると，`git hash-object`と同じ値になる．

```console
$ printf 'blob 6\0hello\n' | sha1sum
ce013625030ba8dba906f756967f9e9ca394464a  -
```

ヘッダーに種類を入れるので，同じバイト列でも，blobとtreeでは別のIDになる．

## SHA-1

SHA-1は，任意の長さのバイト列から160ビット(20バイト)の値を計算するハッシュ関数である．
Gitは，20バイトの値を40桁の16進数で表示する．1バイトが16進数の2桁になる．

- 入力が少し違うだけで，出力は大きく変わる．
- 出力から入力を求めることや，同じ出力になる別の入力を探すことは，計算量の上で難しい．

SHA-1には，同じ出力になる2つの入力を意図して作る攻撃が見つかっている．
Gitは，この攻撃を検出する版のSHA-1を使い，SHA-256を使う形式(`git init --object-format=sha256`)も用意している．
`rgit`は，標準の形式であるSHA-1だけを扱う．
