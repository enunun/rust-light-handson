# Iteration 4：treeオブジェクトとファイルのモード

Iteration 4では，treeオブジェクトの内容を解析して表示する．
このノートでは，treeがディレクトリをどう表すかと，その内容のバイト列の形式を説明する．

## treeオブジェクト

blobはファイルの中身だけを持ち，名前を持たない．
ファイルの名前と，どのblobがどのディレクトリにあるかは，treeオブジェクトが表す．
1つのtreeが1つのディレクトリに当たり，エントリーとして，その直下のファイル(blob)とディレクトリ(tree)を持つ．

```text
tree aae2b36            (作業ディレクトリの最上位)
├── blob ce01362  hello.txt
└── tree 5d90422  src
    └── blob f328e4d  main.rs
```

サブディレクトリはtreeのIDで指すので，treeは入れ子になる．
ディレクトリの中身が1バイトでも変われば，そのtreeのIDが変わり，それを指す親のtreeのIDも変わる．
最上位のtreeのIDを見れば，作業ディレクトリ全体が同じかどうかが分かる．

## `git ls-tree`

`git ls-tree`は，treeのエントリーを1行に1つずつ表示する．

```console
$ git ls-tree e5e07f5
100644 blob ce013625030ba8dba906f756967f9e9ca394464a	hello.txt
120000 blob ce013625030ba8dba906f756967f9e9ca394464a	link
100755 blob ce013625030ba8dba906f756967f9e9ca394464a	run.sh
040000 tree 5d90422423db5ef6b431e8b9e60e0baf04b8742a	src
```

各行は`<モード> <種類> <ID>`，タブ，名前である．`git cat-file -p`にtreeを指定しても，同じ形で表示する．
treeでないオブジェクトを指定すると，エラーになる．

```console
$ git ls-tree ce01362
fatal: not a tree object
```

## ファイルのモード

モードは，エントリーが何かを表す数である．Unixのファイルのモードに由来するが，Gitが使うのは次の5つだけである．

| treeの中の表記 | 意味 | 指すオブジェクト |
| --- | --- | --- |
| `100644` | 通常のファイル | blob |
| `100755` | 実行可能なファイル | blob |
| `120000` | シンボリックリンク(blobの中身はリンク先のパス) | blob |
| `40000` | ディレクトリ | tree |
| `160000` | サブモジュール(別のリポジトリのコミット) | commit |

ファイルの読み書きの権限のうち，Gitが記録するのは実行できるかどうかだけである．

## treeの内容のバイト列

treeの内容は，エントリーを並べたバイナリーである．各エントリーは次の形をしている．

```text
<モード> <名前>\0<20バイトのID>
```

- モードは8進数の文字列である．ディレクトリは`40000`で，`ls-tree`の表示(`040000`)と違い，先頭に0が付かない．
- 名前の後ろにNULがあり，そのあとにIDが16進数ではなく20バイトの値のまま続く．
- エントリーの区切りの記号はない．IDが20バイトと決まっているので，次のエントリーの始まりが分かる．

`git cat-file tree <ID>`は，treeの内容をそのまま出力する．`xxd`でバイト列を見られる．

```console
$ git cat-file tree e5e07f5 | xxd | head -8
00000000: 3130 3036 3434 2068 656c 6c6f 2e74 7874  100644 hello.txt
00000010: 00ce 0136 2503 0ba8 dba9 06f7 5696 7f9e  ...6%.......V...
00000020: 9ca3 9446 4a31 3230 3030 3020 6c69 6e6b  ...FJ120000 link
00000030: 00ce 0136 2503 0ba8 dba9 06f7 5696 7f9e  ...6%.......V...
00000040: 9ca3 9446 4a31 3030 3735 3520 7275 6e2e  ...FJ100755 run.
00000050: 7368 00ce 0136 2503 0ba8 dba9 06f7 5696  sh...6%.......V.
00000060: 7f9e 9ca3 9446 4a34 3030 3030 2073 7263  .....FJ40000 src
00000070: 005d 9042 2423 db5e f6b4 31e8 b9e6 0e0b  .].B$#.^..1.....
```

`hello.txt`の後ろの`00`がNULで，その次の`ce 01 36 25 …`がblobのIDの20バイトである．

treeのエントリーは，名前の順に並ぶ．並べ方の細かい規則は，treeを作るIteration 6で扱う．
