# Iteration 5：インデックス

Iteration 5では，インデックス`.git/index`を読み書きし，`git add`と同じようにファイルを登録する．
このノートでは，インデックスの役割と，ファイルの形式を説明する．

## インデックスの役割

インデックスは，次のコミットに入れるファイルの一覧である．ステージングエリアとも呼ぶ．
`git add`は，ファイルの中身をblobとしてオブジェクトデータベースに書き，そのパス，モード，blobのIDをインデックスに登録する．
`git commit`は，作業ディレクトリではなくインデックスからtreeを作る(Iteration 6と7)．

```console
$ git add .
$ git ls-files --stage
100644 ce013625030ba8dba906f756967f9e9ca394464a 0	hello.txt
100644 f328e4d9d04c31d0d70d16d21a07d1613be9d577 0	src/main.rs
```

`git ls-files --stage`の各行は，モード，blobのID，ステージ番号，タブ，パスである．
ステージ番号は，マージの衝突を記録するときに1〜3を使う．`rgit`はマージを扱わないので，常に0である．

インデックスのパスは，作業ディレクトリの最上位からの`/`区切りのパスである．ディレクトリはエントリーにならず，ファイルだけが並ぶ．
`git add`のあとでファイルを変えると，インデックスには古い中身のblobが残る．次の`git add`で新しいblobに置き換わる．

## ファイルの状態

インデックスのエントリーは，blobのIDのほかに，`add`したときのファイルの状態(時刻，大きさ，iノードなど)を持つ．
`git status`は，作業ディレクトリのファイルの状態がインデックスと同じなら，中身を読まずに「変わっていない」と判断する．
すべてのファイルのハッシュを計算し直さずに済むので，大きなリポジトリでも`status`が速い．

`rgit`はファイルの状態をインデックスに書くが，比べるときには使わない(Iteration 9の`status`は，常にハッシュを計算して比べる)．

## インデックスの形式

インデックスは，次の順に並んだバイナリーのファイルである．整数はすべてビッグエンディアンである．

| 部分 | 大きさ | 内容 |
| --- | --- | --- |
| ヘッダー | 12バイト | `DIRC`，版(2)，エントリーの数 |
| エントリー | 可変 | パスのバイト順に，エントリーの数だけ並ぶ |
| 拡張 | 可変 | `TREE`などの拡張．なくてもよい |
| チェックサム | 20バイト | それより前のすべてのバイト列のSHA-1 |

1つのエントリーは，次の欄からなる．

| 大きさ | 欄 |
| --- | --- |
| 4バイト×2 | ctime(秒とナノ秒) |
| 4バイト×2 | mtime(秒とナノ秒) |
| 4バイト×2 | dev，ino |
| 4バイト | モード(`0o100644`など) |
| 4バイト×3 | uid，gid，大きさ |
| 20バイト | blobのID |
| 2バイト | フラグ．下位12ビットがパスの長さ |
| 可変 | パス |
| 1〜8バイト | NUL．エントリーの長さを8の倍数にする |

固定部分は62バイトである．パスが`hello.txt`(9バイト)なら71バイトになり，NULを1つ足して72バイトにする．
長さがちょうど8の倍数になる場合も，NULを8つ足す．パスの終わりを示すNULが，必ず1つ以上あることになる．

`xxd`で，`git add`が書いたインデックスを見る．

```console
$ xxd .git/index
00000000: 4449 5243 0000 0002 0000 0002 6ac2 c31f  DIRC........j...
00000010: 0718 9481 6ac2 c31f 0718 9481 0000 fe00  ....j...........
00000020: 001e 43d4 0000 81a4 0000 0000 0000 0000  ..C.............
00000030: 0000 0006 ce01 3625 030b a8db a906 f756  ......6%.......V
00000040: 967f 9e9c a394 464a 0009 6865 6c6c 6f2e  ......FJ..hello.
00000050: 7478 7400 6ac2 c31f 0718 9481 6ac2 c31f  txt.j.......j...
00000060: 0718 9481 0000 fe00 001e 43d6 0000 81a4  ..........C.....
00000070: 0000 0000 0000 0000 0000 000d f328 e4d9  .............(..
00000080: d04c 31d0 d70d 16d2 1a07 d161 3be9 d577  .L1........a;..w
00000090: 000b 7372 632f 6d61 696e 2e72 7300 0000  ..src/main.rs...
000000a0: 0000 0000 3848 71ac ecef 1aca a1a7 1b6d  ....8Hq........m
000000b0: 8311 b6d4 1fb6 21d3                      ......!.
```

- `4449 5243`が`DIRC`，`0000 0002`が版2，次の`0000 0002`がエントリーの数2である．
- 1つ目のエントリーの`0000 81a4`がモードで，8進数の`100644`である．その3つ後ろの`0000 0006`が大きさ6バイトである．
- `ce01 3625 …`がblobのID，`0009`がパスの長さ9，`hello.txt`の後ろに`00`が1つある．
- 最後の20バイトがチェックサムである．

本物の`git`は，チェックサムが合わないインデックスを読まない．`rgit`も読むときに確かめる．
