# Iteration 6：インデックスからtreeを作り，commitを作る

Iteration 6では，インデックスからtreeオブジェクトを作る`write-tree`と，treeをcommitオブジェクトにする`commit-tree`を作る．
このノートでは，treeのエントリーの並び順，インデックスからtreeを組み立てる手順，commitオブジェクトの形式を説明する．

## インデックスからtreeを作る

インデックスは，`src/main.rs`のような`/`区切りのパスを平らに並べたものである．
treeは，ディレクトリごとのオブジェクトを入れ子にしたものである．
`git write-tree`は，インデックスのパスをディレクトリごとにまとめ，下のディレクトリから順にtreeを書く．

```text
インデックス                 書くtree
hello.txt          ─┐
src/bin/tool.rs     │       tree(src/bin): tool.rs
src/main.rs        ─┘       tree(src):     bin(上のtree)，main.rs
                            tree(最上位):  hello.txt，src(上のtree)
```

インデックスはパスのバイト順に並んでいるので，同じディレクトリの下のパスは連続して並ぶ．
`src/`で始まるパスをまとめて取り出し，`src/`を取り除いたパスの列で，同じ手順をくり返せばよい．

親のtreeは，子のtreeのIDを持つ．子のtreeを書いてIDを得てからでないと，親のtreeの内容は決まらない．

ファイルのないディレクトリはインデックスに現れないので，treeにもならない．Gitは空のディレクトリを記録できない．
エントリーのない最上位のtreeは，空の内容のtree`4b825dc642cb6eb9a060e54bf8d69288fbee4904`になる．

## エントリーの並び順

treeのエントリーは名前の順に並べる．ただし，ディレクトリの名前は，末尾に`/`があるものとして比べる．

```console
$ git ls-tree $(git write-tree)
100644 blob b68025345d5301abad4d9ec9166f455243a0d746	a-b
100644 blob 587be6b4c3f93f93c489c0111bba5596147a26cb	a.txt
040000 tree 90469fccb66c9cff29fedc685038c6d7b9dcafd8	a
```

ディレクトリ`a`は，`a/`として比べられる．`-`(0x2D)，`.`(0x2E)，`/`(0x2F)の順なので，`a-b`，`a.txt`，`a/`の順になる．
単に名前で比べると`a`が先頭に来て，IDが本物の`git`と変わってしまう．
この規則のおかげで，treeのエントリーの順序は，インデックスのパスの順序(`a-b`，`a.txt`，`a/b`)と一致する．

## commitオブジェクト

commitオブジェクトは，ある時点のスナップショット(最上位のtree)に，作者，日時，メッセージと，1つ前のコミット(親)を加えたものである．

```console
$ git cat-file -p 6c04901
tree aae2b3618f4a481bc1bde056dae4b7617edb7e83
author Alice <alice@example.com> 1767225600 +0900
committer Alice <alice@example.com> 1767225600 +0900

first
```

内容はテキストで，次の順に並ぶ．

| 行 | 内容 |
| --- | --- |
| `tree <ID>` | 最上位のtree．1行だけ |
| `parent <ID>` | 親のコミット．最初のコミットにはなく，マージのコミットには2つ以上ある |
| `author <署名>` | 変更を書いた人と，その日時 |
| `committer <署名>` | コミットを作った人と，その日時 |
| 空行 | ヘッダーの終わり |
| メッセージ | 残りすべて．`-m`で渡したメッセージの末尾に改行が付く |

ほかに，署名付きのコミットは`gpgsig`のヘッダーを持つ．`rgit`はこの4種類のヘッダーだけを扱う．

### 署名と時刻

署名は`<名前> <<メール>> <UNIX時刻> <タイムゾーン>`の形である．
UNIX時刻は，1970年1月1日0時(UTC)からの秒数である．タイムゾーンは，UTCからのずれを`+hhmm`か`-hhmm`で書く．
`1767225600 +0900`は，日本時間の2026年1月1日9時である．

作者とコミッターは，ふつう同じである．別人の変更を取り込んだり(`git am`)，履歴を書き換えたり(`git rebase`)すると，コミッターだけが変わる．

### 環境変数による指定

`git commit-tree`は，作者とコミッターを環境変数から読む．環境変数がなければ設定(`user.name`など)を使う．

| 環境変数 | 内容 |
| --- | --- |
| `GIT_AUTHOR_NAME`，`GIT_AUTHOR_EMAIL` | 作者の名前とメール |
| `GIT_AUTHOR_DATE` | 作者の日時．`@<UNIX時刻> <タイムゾーン>`の形で書ける |
| `GIT_COMMITTER_NAME`，`GIT_COMMITTER_EMAIL`，`GIT_COMMITTER_DATE` | コミッターの同じもの |

日時を固定すると，同じtreeとメッセージから，いつ実行しても同じIDのコミットができる．
`rgit`の結合テストは，`rgit`と本物の`git`に同じ環境変数を渡し，コミットのIDが一致することを確かめる．

## コミットのIDが表すもの

コミットのIDは，treeのIDと親のIDを含む内容から計算する．
treeのIDはすべてのファイルの中身から決まり，親のIDはそれまでの履歴全体から決まる．
そのため，コミットのIDが同じなら，その時点のファイルも，そこに至る履歴もすべて同じである．
過去のコミットを1つでも書き換えると，それより後のすべてのコミットのIDが変わる．
