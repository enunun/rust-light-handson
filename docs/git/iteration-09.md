# Iteration 9：HEAD，インデックス，作業ディレクトリ

Iteration 9では，`git status`のように，ファイルの変更の状態を表示する．
このノートでは，`status`が比べる3つの状態と，`git status --porcelain`の表示の形を説明する．

## 3つの状態

Gitのファイルには，3つの状態がある．

| 状態 | 中身 | 変える操作 |
| --- | --- | --- |
| HEAD | 最後のコミットのtree | `git commit` |
| インデックス | 次のコミットに入れる予定のファイル | `git add` |
| 作業ディレクトリ | 今のファイル | 編集 |

`git status`は，HEADとインデックス，インデックスと作業ディレクトリの2組を比べる．

- HEADとインデックスの違いは，`git commit`で次のコミットに入る変更である(ステージされた変更)．
- インデックスと作業ディレクトリの違いは，まだ`git add`していない変更である．
- インデックスにない作業ディレクトリのファイルは，追跡されていないファイルである．

3つの状態は，どれもパスからモードとblobのIDへの表として比べられる．
HEADのtreeは入れ子なので，サブディレクトリまでたどって，インデックスと同じ`src/main.rs`の形のパスの表にする．
作業ディレクトリのファイルは，中身のハッシュを計算してblobのIDにする．

## `git status --porcelain`

`--porcelain`は，プログラムが読みやすい形に整えて表示する．`-uall`は，追跡されていないディレクトリの中のファイルも1つずつ表示する．

```console
$ git status --porcelain -uall
MM b.txt
 D d.txt
M  m.txt
A  n.txt
 M x.sh
?? a.txt
?? sub/u.txt
```

各行は2文字の状態，空白，パスである．1文字目(X)はHEADとインデックスの違い，2文字目(Y)はインデックスと作業ディレクトリの違いを表す．

| 文字 | X(HEADとインデックス) | Y(インデックスと作業ディレクトリ) |
| --- | --- | --- |
| `A` | インデックスに加わった | 使わない |
| `M` | 中身かモードが変わった | 中身かモードが変わった |
| `D` | インデックスから消えた | 作業ディレクトリから消えた |
| 空白 | 同じ | 同じ |

上の例は，次の操作をしたあとの表示である．

- `b.txt`：変えて`add`し，さらに変えた(`MM`)．
- `d.txt`：作業ディレクトリから消した(Xが空白，Yが`D`)．
- `m.txt`：変えて`add`した(Xが`M`，Yが空白)．
- `n.txt`：新しく作って`add`した(Xが`A`，Yが空白)．
- `x.sh`：実行できるようにした．中身は同じでも，モードが変われば変更である(Xが空白，Yが`M`)．
- `a.txt`と`sub/u.txt`：新しく作ったが，`add`していない(`??`)．

変更のあるファイルをパスの順に並べ，そのあとに追跡されていないファイルをパスの順に並べる．

## 速さの工夫

作業ディレクトリのファイルをすべて読んでハッシュを計算すると，大きなリポジトリでは時間がかかる．
本物の`git`は，インデックスに記録したファイルの状態(Iteration 5)と，今のファイルの状態を比べる．時刻や大きさが同じなら，中身を読まずに「変わっていない」と判断する．

`rgit`の`status`は，常にすべてのファイルのハッシュを計算する．Iteration 11で，この計算を複数のスレッドで行う．
