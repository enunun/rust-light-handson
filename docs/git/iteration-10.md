# Iteration 10：差分とunified形式

Iteration 10では，`git diff`のように，ファイルのどの行が変わったかを表示する．
このノートでは，`git diff`が比べるもの，2つの列の最短の編集を求めるMyersのアルゴリズム，unified形式の読み方を説明する．

## `git diff`が比べるもの

`git diff`は，Iteration 9の3つの状態のうち，隣り合う2つを比べる．

| コマンド | 古い側 | 新しい側 |
| --- | --- | --- |
| `git diff` | インデックス | 作業ディレクトリ |
| `git diff --cached` | HEAD | インデックス |

`git diff`は，まだ`add`していない変更を表示する．`git diff --cached`は，次のコミットに入る変更を表示する．
どちらも，`status`と同じく，違うファイルをパスの順に並べる．インデックスにないファイルは，`git diff`には現れない．

## 最短の編集

古いファイルの行の列を`a`，新しいファイルの行の列を`b`とする．
`a`の行を消すか，`b`の行を挿入するかして`a`を`b`に変える手順のうち，消す行と挿入する行の合計が最も少ないものを求める．
残った行は，`a`と`b`で一致する行である．

```text
a = [a, b, c]
b = [a, c, d]

  a      一致
- b      削除
  c      一致
+ d      挿入
```

### 編集グラフ

`a`を横に，`b`を縦に並べた格子を考える．点`(x, y)`は，「`a`の先頭`x`行と`b`の先頭`y`行を処理した」状態を表す．

- 右へ1つ進む：`a`の行を1つ消す．
- 下へ1つ進む：`b`の行を1つ挿入する．
- 右下へ斜めに進む：`a[x]`と`b[y]`が等しいときだけ進め，どちらも残す．

左上`(0, 0)`から右下`(n, m)`までの道のうち，右と下の移動の最も少ない道が，最短の編集である．斜めの移動は数えない．

### Myersのアルゴリズム

1986年にEugene Myersが発表した方法で，`git`の差分の基本になっている．
`x - y`を`k`とすると，同じ`k`の点は同じ対角線の上にある．右に進むと`k`が1増え，下に進むと`k`が1減る．
右と下の移動を`d`回使ってたどり着ける点は，対角線`k = -d, -d + 2, …, d`の上にしかない．

アルゴリズムは`d = 0, 1, 2, …`の順に，各対角線で最も右下まで進んだ点の横の位置を`v[k]`に記録する．

1. `d`回目は，`d - 1`回目の隣の対角線(`k - 1`か`k + 1`)のうち，遠くまで進んだほうから右か下へ1つ進む．
2. そこから，行が一致する限り斜めに進む．
3. 右下`(n, m)`に着いたら終わる．そのときの`d`が，最短の編集の長さである．

`a = [a, b, c]`，`b = [a, c, d]`の例である．

| `d` | 対角線`k` | 来た向き | 斜めに進んだあとの点 |
| --- | --- | --- | --- |
| 0 | 0 | 始点 | `(1, 1)`(`a`が一致) |
| 1 | -1 | 下(挿入) | `(1, 2)` |
| 1 | 1 | 右(削除) | `(3, 2)`(`c`が一致) |
| 2 | 0 | 対角線1から下(挿入) | `(3, 3)`：終点 |

最短の編集の長さは2である．終点から，各段階でどの対角線から来たかを逆にたどると，編集の列が決まる．
`d`回目の計算で使うのは，`d - 1`回目の`v`だけである．終点から逆にたどれるよう，各段階の`v`を記録しておく．

行の数をN，編集の長さをDとすると，計算の量は多くてもおよそN×Dである．変更の少ないファイルほど速い．

### 記録の量

逆にたどるための記録は，メモリーを使う．
各段階の`v`を丸ごと記録すると，記録の量はN×Dに比例する．段階`d`で読む対角線`-d - 1`から`d + 1`までだけを記録すれば，D×Dに比例する量で済む．
それでも，中身をすべて書き換えたファイルではDがNの2倍になり，記録が大きくなる．

本物の`git`(xdiff)は記録を残さない．最短の経路が必ず通る中間の点を，始点と終点の両側から進めて見つけ，その前と後ろを別々に解く．
この方法では，メモリーの量は行の数に比例する量で済む．

### `git`との違い

最短の編集が複数あるとき，どれを選ぶかは実装によって違う．
本物の`git`は，Myersのアルゴリズムで求めた編集を，さらに読みやすく整える．離れた変更を同じ行の上で滑らせて1つにまとめ，字下げを手がかりに区切りの位置を選ぶ．
そのため，`rgit`と`git`は，長さは同じでも違う編集を表示することがある．

```console
$ printf 'a\nb\nb\n' > f.txt
$ git add f.txt
$ printf 'b\n' > f.txt
$ git diff
diff --git a/f.txt b/f.txt
index ee12596..6178079 100644
--- a/f.txt
+++ b/f.txt
@@ -1,3 +1 @@
-a
-b
 b
$ rgit diff
diff --git a/f.txt b/f.txt
index ee12596..6178079 100644
--- a/f.txt
+++ b/f.txt
@@ -1,3 +1 @@
-a
 b
-b
```

どちらも2行を消す編集で，結果は同じ`b`になる．`git`は，2つの削除を1つにまとめている．

## unified形式

`git diff`は，差分をunified形式で表示する．

```console
$ git diff
diff --git a/hello.txt b/hello.txt
index ce01362..94954ab 100644
--- a/hello.txt
+++ b/hello.txt
@@ -1 +1,2 @@
 hello
+world
```

| 行 | 意味 |
| --- | --- |
| `diff --git a/<パス> b/<パス>` | ファイルの差分の始まり．`a/`は古い側，`b/`は新しい側 |
| `index <古いID>..<新しいID> <モード>` | 両側のblobのIDの先頭7文字と，モード |
| `--- a/<パス>`と`+++ b/<パス>` | 古い側と新しい側の名前 |
| `@@ -<開始>,<行数> +<開始>,<行数> @@` | ハンクの見出し |
| 空白で始まる行 | 両側で一致する行(文脈) |
| `-`で始まる行 | 古い側から消えた行 |
| `+`で始まる行 | 新しい側に加わった行 |

### ハンク

変更のある行と，その前後3行の文脈をまとめたものをハンクと呼ぶ．
2つの変更の間の一致する行が6行(文脈の2倍)以下なら，2つのハンクは1つにまとまる．

1から20までの数を1行ずつ書いたファイルの，3行目と9行目を変え，末尾に`21`を加えた例である．

```console
$ git diff
diff --git a/numbers.txt b/numbers.txt
index 0ff3bbb..8cdb13d 100644
--- a/numbers.txt
+++ b/numbers.txt
@@ -1,12 +1,12 @@
 1
 2
-3
+three
 4
 5
 6
 7
 8
-9
+nine
 10
 11
 12
@@ -18,3 +18,4 @@
 18
 19
 20
+21
```

3行目と9行目の変更の間には，一致する行が5行しかないので，1つのハンクになる．
見出しの`-1,12`は「古い側の1行目から12行」，`+18,4`は「新しい側の18行目から4行」を表す．
行数が1なら，`@@ -1 +1,2 @@`のように行数を省く．行数が0のときは，開始にその直前の行の番号を書く(空のファイルからの追加なら`-0,0`)．

ハンクの見出しの`@@`の後ろには，ハンクより前にある関数の名前などの行を付けることがある．既定では，英字，`_`，`$`で始まる行を探す．`rgit`はこれを出力しない．

### ファイルの追加，削除，モードの変更

`d.txt`と`x.sh`をコミットしたあと，`d.txt`を消し，`n.txt`を作り，`x.sh`を実行できるようにして`git add .`した例である．

```console
$ git diff --cached
diff --git a/d.txt b/d.txt
deleted file mode 100644
index 4bcfe98..0000000
--- a/d.txt
+++ /dev/null
@@ -1 +0,0 @@
-d
diff --git a/n.txt b/n.txt
new file mode 100644
index 0000000..3e75765
--- /dev/null
+++ b/n.txt
@@ -0,0 +1 @@
+new
diff --git a/x.sh b/x.sh
old mode 100644
new mode 100755
```

- 追加されたファイルは`new file mode`の行を持ち，古い側のIDを`0000000`，名前を`/dev/null`にする．削除はその逆である．
- モードの変わったファイルは，`old mode`と`new mode`の行を持つ．中身が同じなら，`index`の行とハンクはない．
- 空のファイルを追加したときは，ハンクがないので，`---`と`+++`の行もない．

### 末尾の改行とバイナリーファイル

末尾に改行のない`abc`を`abd`に変え，NULを含む`a\0b`を`a\0c`に変えた例である．

```console
$ git diff
diff --git a/bin.dat b/bin.dat
index 20b5be9..88f3700 100644
Binary files a/bin.dat and b/bin.dat differ
diff --git a/nonl.txt b/nonl.txt
index f2ba8f8..d4a5aa5 100644
--- a/nonl.txt
+++ b/nonl.txt
@@ -1 +1 @@
-abc
\ No newline at end of file
+abd
\ No newline at end of file
```

- 最後の行に改行がないとき，その行の後ろに`\ No newline at end of file`を出力する．`abc`と`abc`に改行を付けた行は，違う行として比べる．
- 中身にNUL(`0x00`)を含むファイルは，バイナリーファイルとみなし，行の差分を出さない．本物の`git`は，先頭の8000バイトだけを調べる．

`index`の行のIDは，本物の`git`では，ほかのオブジェクトと区別できるだけの長さ(7文字以上)になる．`rgit`は常に7文字にする．
