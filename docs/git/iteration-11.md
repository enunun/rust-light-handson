# Iteration 11：オブジェクトの書き込みと並列化

Iteration 11では，`add`と`status`のファイルの処理を複数のスレッドで行う．
このノートでは，ファイルごとの処理を並列にできる理由と，複数のスレッドやプロセスが同時にオブジェクトを書いても壊れない書き方を説明する．

## 並列にできる処理

`add`は，ファイルごとに次の処理をする．

1. ファイルを読む．
2. ヘッダーを付けてSHA-1を計算する．
3. zlibで圧縮し，`.git/objects`に書く．
4. インデックスのエントリーを作る．

`status`と`diff`は，作業ディレクトリのファイルごとに1と2をする．
どのファイルの処理も，ほかのファイルの結果を使わない．別々のスレッドで同時に進められる．
計算の時間の多くは，ハッシュと圧縮である．CPUのコアが多いほど速くなる．

インデックスは1つのファイルなので，書くのは最後に1回だけである．
各スレッドはエントリーを返すだけにし，インデックスへの登録と保存は1つのスレッドで行う．

## 同じオブジェクトを同時に書く

`a.txt`と`b.txt`の中身が同じなら，2つのスレッドが同じIDのオブジェクトを同時に書くことがある．
IDは中身から決まるので，2つのスレッドが書く内容は同じである(Iteration 2)．書く内容の食い違いは起きない．

問題になるのは，書いている途中のファイルである．

- ファイルを書いている途中で，ほかのスレッドやプロセスがそのファイルを読むと，途中までの内容を読んでしまう．
- 2つのスレッドが同じファイルに同時に書くと，片方が書いている途中のファイルを，もう片方が開いて空に切り詰めることがある．
- 書いている途中でプロセスが止まると，壊れたオブジェクトが残る．以後，そのIDのオブジェクトは「ある」とみなされて書き直されない．

## 一時ファイルと名前の変更

これを防ぐため，オブジェクトをまず別の名前の一時ファイルに書き，書き終えてから正しい名前に変える．

```text
.git/objects/ce/tmp_obj_4242_0             ← ここに書く(名前は例)
.git/objects/ce/013625030ba8dba906f756967f9e9ca394464a  ← 書き終えたら名前を変える
```

同じファイルシステムの中の名前の変更(`rename`)は，原子的に行われる．
ほかのプロセスからは，「正しい名前のファイルがない」か「書き終えたファイルがある」かのどちらかにしか見えない．
すでに同じ名前のファイルがあれば，新しいファイルに置き換わる．中身は同じなので，置き換わっても問題ない．

- 一時ファイルは，オブジェクトと同じディレクトリに作る．別のファイルシステムの間では，名前の変更が使えないからである．
- 一時ファイルの名前は，同時に書くほかのスレッドやプロセスと重ならないようにする．`rgit`はプロセスID(`std::process::id`)と，プロセスの中で増やす番号を使う．

本物の`git`も，`.git/objects`の下に`tmp_obj_`で始まる名前の一時ファイルを作り，書き終えてから正しい名前にする．
Iteration 7のロックファイルも同じ考え方で，書き終えたファイルの名前を変えて置き換える．

## 書いたオブジェクトを`git fsck`で確かめる

`git fsck`は，リポジトリのすべてのオブジェクトを読む．IDと中身の一致と，参照の指すオブジェクトの有無を調べる．
問題がなければ何も出力しない．

```console
$ rgit add --jobs 4 .
$ rgit commit -m first
[main (root-commit) 791b777] first
$ git fsck
```

`rgit`の結合テストでは，並列に`add`してから`git fsck`を実行し，オブジェクトが壊れていないことを確かめる．

## 本物の`git`の並列化

本物の`git`も，いくつかのコマンドでスレッドを使う．

| 設定 | 並列にする処理 |
| --- | --- |
| `core.preloadIndex` | `status`や`diff`で，インデックスのファイルの状態を調べる処理(既定で有効) |
| `checkout.workers` | `checkout`で，作業ディレクトリにファイルを書く処理 |
| `pack.threads` | パックファイルを作るときの，差分の探索 |

どれも，ファイルやオブジェクトごとの独立した処理を分け，結果を1か所にまとめる形である．
